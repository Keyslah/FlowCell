FlowCell Program Summary
Last updated: 2026-07-08

Purpose
-------
FlowCell is a Windows desktop command surface for program-specific panels, script buttons, popouts/fans, Blender bridge actions, layout restore, and local runtime automation.

Current Direction
-----------------
- Keep the app on the rolled-back stable base with the backend/runtime rooted at `flowcellbackend/`.
- Preserve the Blender cycle/collection/tool work that existed at commit `03796bb`.
- Do not reintroduce the later Appearance/SkinPort/live skin work unless it is rebuilt as a narrow, clean V2 slice.
- Treat `PROGRAM_SUMMARY.txt` as an orientation map, not a changelog or bug diary. Detailed fixes belong in commits, issue notes, or feature docs.

Repository Map
--------------
- `FlowCellFrontend/` is the active Tauri + React frontend.
- `FlowCellFrontend/src-tauri/src/main.rs` owns native commands, path resolution, dialogs, script execution bridges, and file/layout persistence.
- `FlowCellFrontend/src/lib/windowing.ts` owns managed window creation and sizing for popouts, fans, toolboxes, layout picker, settings, and utility windows.
- `flowcellbackend/` is the canonical backend/runtime folder.
- `flowcellbackend/FlowCellBackend.ahk` is the live AutoHotkey backend for hotkeys, direct script receiver, macro handling, and backend-run actions.
- `flowcellbackend/FlowCellCommandBackend.ps1` is the PowerShell command host used by backend actions.
- `flowcellbackend/helpers/Start-FlowCellFrontend.ps1` is the standard frontend stop/build/relaunch entrypoint.
- `flowcellbackend/local/` is ignored durable runtime state: bindings, layouts, logs, private config, temp files, theme packages, and generated local data.
- `FlowCell/local/` is legacy ignored local state only. It is not the active runtime source.
- `Programs/` contains program-specific panels, Git Scripts, support scripts, generated panel items, and bridge payloads.

Runtime Contracts
-----------------
- Program rail registration and shortcut bindings are read from `flowcellbackend/local/bindings.ini`.
- Startup preflight repairs built-in program registrations from existing `Programs/<Program>` folders before frontend launch.
- The default built-in program tabs are Illustrator, Windows, Blender, and Photoshop when their folders are present.
- Program panel buttons execute through the shared script runner; Windows scripts run as generic Windows actions without forcing Explorer focus first.
- Mutable user/runtime data must stay under `flowcellbackend/local/`, not in tracked source folders.
- Deletions from user-facing flows must go to the Recycle Bin unless the user explicitly asks for permanent deletion.
- Managed windows and layouts should restore from saved bounds without guessing monitor layout or silently changing window geometry.

Frontend Surfaces
-----------------
- Main page owns the program rails, panel buttons, Add Program flow, top-left actions, and main-window Space-drag behavior.
- Popouts, panel fans, toolboxes, utility windows, settings, layout picker, Window Grid, Binds, Macro Lab, and Organization Setup are separate managed Tauri windows.
- Layout save/load stores managed window bounds and startup settings; the main window can restore the last layout on startup.
- Organization Setup is a managed React window backed by Windows support scripts and saved profile data under `flowcellbackend/local/Folder Tree Profiles` and `flowcellbackend/local/Folder Trees`.
- Appearance V1 / SkinPort / live imported-skin wiring is not the current direction after the rollback. Any future button visual work should be a clean-room V2 vertical slice, scoped before broad wiring.

Blender And Program Bridges
---------------------------
- Blender actions should route through `Programs/Blender` sources and support scripts, then into the installed FlowCell Blender add-on or action registry.
- Blender bridge changes usually require reloading the FlowCell Blender add-on or restarting Blender.
- Cycle Collection, Boolean, Alignment, Snapshot, Theme, Place Picture, and related Blender tools should keep their source-of-truth scripts in the Git Scripts/support-script path, not in generated local copies.
- Illustrator bridge and layer tooling use `Programs/Illustrator` support scripts and store shared runtime state under `flowcellbackend/local`.
- Windows utility scripts under `Programs/Windows/Windows Git Scripts` should write status/log/config data through `flowcellbackend/local`.

Validation
----------
- For frontend/Tauri changes, run the relevant frontend build before finishing. Prefer `flowcellbackend/helpers/Start-FlowCellFrontend.ps1 -ForceRestart` when the running app must be refreshed.
- For backend AutoHotkey changes, validate `flowcellbackend/FlowCellBackend.ahk` with AutoHotkey v2 and restart the hidden backend.
- For PowerShell support-script changes, parse touched `.ps1` files and run the narrow behavior check when possible.
- For Blender bridge changes, verify both source scripts and any live/generated add-on copies that must be reloaded.
