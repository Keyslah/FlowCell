FlowCell Program Summary
Last updated: 2026-06-19

Purpose
-------
FlowCell is the desktop frontend, command host, program folders, local runtime state, and Blender bridge workflow.

Current frontend state
----------------------
- `FlowCellFrontend/src/pages/main/mainLayout.ts` keeps the main window source-coded from the repo SVG layout using fixed coordinates rather than a runtime-generated page builder.
- Program script storage now uses a Git/local/panel split under `Programs\<Program>\`: tracked shared sources live in `<Program> Git Scripts` with panel subfolders, ignored durable private backups live flat in `<Program> Local Scripts`, and ignored `Panels\<Panel>` folders keep the runnable panel script copies or Blender panel records. `Add Script` and Blender `Add Button` open from Git Scripts when available, copy selected files into Local Scripts without deleting prior local copies, copy runnable scripts into the selected panel folder, and Blender panel records now point at the panel-local `.py` source. Generic/custom programs now use the same Add Script workflow as Windows-style script panels, creating `<Program> Local Scripts` on demand and listing/running/deleting the resulting panel-local copies through the simple script path. The old `ScriptBank`, `Active Scripts`, and legacy `<Program> Scripts` library folders were removed from the active workflow; `ScriptDump` remains fully ignored local scratch space with no tracked placeholder files.
- The top-left chrome row now contains `Save Layout`, `Load Layout`, `Binds`, `Macro Lab`, and `Refresh`; `Macro Lab` opens the single-active macro editor for the selected program/panel, while `Refresh` still uses the frontend host restart path and `FlowCell/helpers/Start-FlowCellFrontend.ps1` still serializes overlapping launch/restart requests behind a named launcher lock, targets the packaged `src-tauri\target\release\flowcell_frontend.exe` by default, recognizes stale same-repo debug/release frontend processes during restart, rebuilds the release binary instead of the debug binary so normal launches do not fall back onto the wrong runtime shell, skips the redundant second stop when a force restart also needs a rebuild so dirty-source refreshes no longer abort before the rebuild step, normalizes blank native window handles during focus checks, always launches a fresh frontend after an explicit force restart instead of accidentally reusing an exiting process, and now attempts to restart the last compiled frontend after a rebuild failure so a bad refresh build is less likely to leave the desktop app dead.
- `Binds` now opens a dedicated bind station window with a top target mode switch for panel buttons or standalone macros, selectors for the active target, a typeable `Shortcut` field, and `Bind`; the current-panel button list remains on the left and the grouped global button picker remains on the right.
- The `Shortcut` field in `Binds` is now a typeable manual-entry box with a click-open safe-suggestions menu; available suggestions come from the conservative master candidate pool filtered through `Windows` plus the selected program shortcut profile plus current FlowCell binds, typed shortcuts are still blocked when reserved or already in use, and standalone macros plus Core actions bind through `ActionHotkeys` without requiring a panel button.
- The top `Macro Lab` button opens one single-active React/Tauri macro editor that discards the previous draft on reopen, edits standalone managed macro INI files under `FlowCell\local\recorded_actions`, loads any macro `.ini` through a file-picker button beside `New Macro`, shows live mouse X/Y beside the step editor coordinate fields, uses a same-row `Pick` button that writes the screen cursor position into `X`/`Y` after two seconds, supports desktop-style step row selection, step editing, undo/redo, save/copy/rename/delete/run/global-record actions, and refreshes macro-aware windows after saves or deletes.
- The main buttons surface has a separate `Add Macro` button beside `Add Script`; only that explicit attach flow creates one stable ID-backed `.flowcell-panel-item.json` macro button in the selected panel after a non-empty macro is saved or recorded.
- Macro panel buttons carry stable macro IDs, run through the existing FlowCell `flowcell.run_macro` command backend path, and use `ActionHotkeys` in `FlowCell\local\bindings.ini` for Binds instead of script-path bindings.
- Saving or clearing a bind from `Binds` now also restarts the hidden FlowCell AutoHotkey backend so the updated hotkey registration goes live immediately instead of waiting for a manual backend restart.
- Default shortcut profiles now live under `FlowCell\config\shortcut_profiles`, optional user overrides can live under `FlowCell\local\shortcut_profiles`, and binding persistence still writes through the existing `FlowCell\local\bindings.ini` path.
- The appearance editor system has been removed from the active app path. There is no Appearance page, no draft window entrypoint, no saved skin library, no per-button skin assignment store, and no tool-set layout override store in the frontend runtime.
- Program and panel rails are populated from repo folders under `Programs\` and `Programs\<Program>\Panels\`; right-clicking a program or panel rail button now exposes `Rename` and `Delete` actions that rename the backing folder or move it to the Recycle Bin.
- Illustrator's `Layers` panel now has the restored 20 layer-management scripts copied directly under `Programs\Illustrator\Panels\Layers`, with the local legacy FlowCell state pointing the Illustrator Layers buttons at those folder-local copies and with plain top-of-file descriptions for each layer-management button, including Snapshot. Illustrator panel script clicks now validate the backend/runtime and send the clicked JSX to the already-running hidden AutoHotkey backend through a direct Windows-message receiver without a FlowCell queue, queue drain, status popup, frontend wait/kill timeout, per-click AutoHotkey process startup, or native File-menu automation; the backend runs the panel-local JSX through Illustrator COM with `DoJavaScriptFile`. On the main FlowCell surface, normal Illustrator panel-script clicks use the standard main-button contract: single-click toggles selection for Pop/Fan/order workflows, Ctrl/Shift/Meta-click still toggles selection immediately, and double-click runs or opens the script action. The 20-button Layers popout still sends the clicked JSX to the live backend without awaiting a host accept response, and visible FlowCell controls explicitly own their pointer hitboxes. Illustrator toolset actions validate only the clicked toolset file instead of rescanning the whole panel folder per click, use high-resolution direct request ids for rapid clicks, and the Illustrator anchor `V` pass-through hotkey now dispatches through the live backend instead of spawning the old command host. The hidden backend also runs a silent no-op Illustrator JSX prewarm when stable Illustrator appears, keeps that automation path warm only while idle, and logs direct script runtime without repeating successful keepalive spam.
- User-triggered automation-only Illustrator direct actions now foreground the stable Illustrator window immediately before COM while the silent prewarm path stays background-only, so visible Illustrator changes repaint without waiting for the pointer to leave a FlowCell tool window.
- The Illustrator `delete sublayer` layer script is based on the earliest restored March 23 implementation, with only the target rule changed: each selected object resolves to its immediate owning layer, never climbs upward to family/root containers such as `Snapshots > pins`, and does not delete empty ancestors after deleting that owner. The top-level `Live`, `Snapshots`, `Trash`, and `Archive` roots remain protected by deleting a direct-root item only instead of deleting the root layer. The current June script version logs timing around actual `layer.remove()` and `item.remove()` calls for native-menu fast-path verification.
- Illustrator Layers `snapshot`, `back`, `trash`, `archive`, `3D`, and `3D test` scripts now resolve normal button targets directly from `app.activeDocument.selection` and the selected item/layer parent chain instead of doing per-click selected-object discovery crawls through the full layer tree or page-item lists. Snapshot and 3D container ordering now reads only direct Live root children during ordinary clicks, `snapshot` tries a native layer duplicate before recursive copy, `back` detaches the Illustrator selection before structural layer moves, tries layer/item move restore paths that move the current Live target to Trash and move the consumed snapshot layer or contents back into Live before falling back to copy/clear, leaves the restored Live layer active with its artwork selected instead of re-highlighting the moved Trash copy, and `trash`/`archive` no longer capture every descendant state before moving a whole selected layer. The `trash` action now resolves each selected object to its immediate owning layer from any non-Trash root before moving that whole owner into Trash, with direct root-level artwork still moved as an item so protected root folders are not moved; versioned system roots keep the moved owner layer but name the Trash family with the version prefix plus owner name, for example `Snapshots > fuckyou > s3` becomes `Trash > s3fuckyou > Tn`. `Sort` temporarily unlocks `Live` folders for routing but restores their locked states afterward, including child folders moved into newly created Live containers. `b lock` and `set lock` now write their own temp debug log; `set lock` verifies whether each Illustrator lock assignment sticks and redraws Illustrator after applying the baseline. The Layers scripts write staged timing lines for command receipt, selection read, snapshot/root lookup, action, and total runtime to `FlowCell\local\logs\illustrator-layers.log`; child-layer checks stay on direct sibling loops to avoid Illustrator `getByName` COM stalls/errors.
- Illustrator's `Utility` panel exposes the anchor alignment workflow as one `Ill Align` toolset button. When the Illustrator payload is installed, Binds adds a virtual `Illustrator > Actions > Set Anchor` Core action that is not shown in any panel; the user chooses its shortcut, and the hotkey is active only while Illustrator is foreground. Running it captures the selected PageItem or combined selection visible-bounds box and center point in `FlowCell\local\illustrator_anchor_bounds.json`. The alignment toolset reuses the FlowCell toolbox window path with Illustrator-scoped topmost, X/Y rows only, and bottom `Art`, `Anchor`, and toggleable `Group` controls. The Ill Align backend uses Illustrator's global `app.selection` first, uses `visibleBounds` consistently, consumes `FlowCell\local\illustrator_anchor_command.json` after each command so stale actions do not replay, falls back to ExtendScript `eval` when `JSON.parse` is unavailable, and logs status to `FlowCell\local\logs\illustrator-anchor.log`; alignment move buttons fire on pointer-down, write the command payload, and send the anchor engine JSX to the live backend receiver without a frontend wait/kill timeout or per-click AutoHotkey startup, `Art` centers every selected page item on the active artboard, `Anchor` centers every selected page item on the stored anchor, `Group` moves the selected items as one combined bounds box, center actions clear Surface/Origin UI state, and Surface+Min/Max are explicit opposite-edge commands.
- `Programs\Illustrator\Illustratoralign.md` documents the FlowCell Illustrator `Ill Align` toolset as a button-by-button reference for the X/Y edge, center, surface, origin, artboard, anchor, and group controls.
- Illustrator now also has an `Illustrator Rotate` toolset in the Utility and Toolset panels plus a shared source copy under `Programs\Illustrator\Illustrator Git Scripts`; its Illustrator variant uses the literal updated `oRotate.svg` capsule geometry with the taller top-row `Art`, `Anchor`, `30`, `45`, and `90` controls, fixed single-axis Illustrator rotation, `Transform`/`Distribute` modes, a bottom field, and `Negative`/`Positive` apply buttons. In `Transform`, the bottom field is degrees and the `30`/`45`/`90` buttons write that degree value into the bottom field, switch/apply Transform immediately, and leave the value available for Negative/Positive. In `Distribute`, the bottom field is total positions including the original selection, so `3` creates two rotated copies evenly spaced around the pivot. Overlapping Illustrator rotate clicks are ignored while an action is already running, Illustrator rotate buttons fire on pointer-down, Illustrator rotate commands use the live backend receiver plus automation-only Illustrator COM so clicks do not spawn the old controller CLI or launch Illustrator with a script path, write a timestamped `FlowCell\local\illustrator_rotate_command.json` payload that the JSX consumes after start so stale commands cannot replay, `Art` rotates around the active artboard center through one Illustrator matrix transform instead of a rotate-then-translate sequence, and `Anchor` rotates every selected object around the stored anchor center without requiring multiple selected objects or excluding the item that captured the anchor. Rotate actions log command requests and results to `FlowCell\local\logs\illustrator-rotate.log`.
- FlowCell Core owns `Add Program`. It creates or registers only the direct `Programs\<ProgramName>` folder and never creates panels, setup buttons, or macros; users create panels manually through `Add Panel`, which remains the only panel creator and immediately selects the new visible panel. Wrapper/package folders such as `Programs\FlowCell-Blender` are filtered by the backend program listing.
- Optional program payload ZIPs contain only `Programs\<ProgramName>` and merge directly into the FlowCell Core root; the Core ZIP contains the full app with an empty `Programs` folder. There is no combined all-program package.
- When `Add Program` detects `blender.exe` and the Blender payload exists, Core directly runs the payload installer to copy/repair the bridge in the detected Blender version's user `scripts\addons` folder, writes a startup bootstrap that enables/registers `flowcell_actions.py`, and reports that Blender must be restarted once after adding Blender. If Blender settings do not exist yet, Blender stays added and FlowCell tells the user to open Blender once, close it, then restart FlowCell.
- Adobe-created program rails support panel `Add Script`/`Run` for `.jsx` and `.js` files through the existing FlowCell AutoHotkey controller path; Illustrator panel scripts use the same automation-only COM route as Illustrator toolsets instead of launching Illustrator with a script path, and prompt/alert/confirm JSX scripts start asynchronously from the frontend and foreground the stable Illustrator window before COM so Illustrator modal dialogs do not freeze FlowCell while waiting for user input.
- Blender `Add Script` now preserves the selected panel name on generated Blender config button entries, and the Blender description/delete maintenance helpers keep that panel ownership intact so Utility imports do not become unscoped buttons that can surface across other panels.
- The Tauri frontend now exposes the missing generic open/save file and folder dialog commands that the existing frontend helper layer expects, so `Add Program` and other desktop file-pick flows no longer fail on a missing invoke command before the dialog appears.
- Windows script state and shortcut migration now treat old repo-root `Windows\...` paths as legacy aliases for `Programs\Windows\...`, FlowCell restores the default `Ctrl+Shift+F2` dummy-monitor binding to the Windows Utility `Launch-DummyMonitorToggle.vbs` launcher when no saved bind is present, and the Windows Utility panel keeps that VBS launcher as the only visible dummy-monitor button while it runs the repo-owned `Programs\Windows\Panels\Utility\dummy_monitor_toggle.py --toggle-once --target-display AOC28E850.HDR` through Aaron's Python 3.11 path; related monitor-layout helper scripts now also prefer that repo-owned panel copy.
- Windows `Files` actions that operate on external folders or repositories now require an explicit clipboard path and show a no-valid-clipboard-path error when none is available. `Update GitHub`, `GitHub Pull`, `GitHub Backup`, `FlowCell Backup`, and `Organize Folder` no longer fall back to environment overrides, the active Explorer window, picker dialogs, or the FlowCell repo root.
- The Windows `Files` panel now uses `organize_folder.ps1`, backed by `Programs\Windows\SupportScripts\Organize-FolderCore.ps1`, to organize copied project folders into `01 src\00 assets`, `02 builds`, `03 releases`, and `04 archive` while preserving existing numbered program folders. Program live/snapshots/archive/trash folders are created only for detected saved program files, unknown files go to `00 assets\05 unknown`, and empty unexpected directories are moved to the Recycle Bin. Each completed run writes both `organize-folder.log.txt` and a machine-readable `organize-folder.undo.json` rollback manifest, while likely parent folders containing multiple project-like child folders warn and stop before changes.
- The portable AutoHotkey v2 on/off toggle now lives under `tools\autohotkey v2 on off` instead of the Windows Utility scripts. It includes `Toggle-AutoHotkey.vbs`/`Toggle-AutoHotkey.ps1`, tracked green/on and red/off shortcut icons, and `docs/toggle-autohotkey-for-anticheat.md`, letting any GitHub checkout toggle all AutoHotkey processes off for anti-cheat games and restore the saved snapshot or managed launcher list without Aaron-specific paths. The toggle waits for AutoHotkey process state before changing feedback, keeps the shortcut green/on if any AutoHotkey process is still running, and writes text plus JSON status under `FlowCell\local\autohotkey-toggle`.
- Blender add-on templates now live under `Programs\Blender\Blender Addons - Copy contents Into Blender`, a paste-ready bundle containing `flowcell_actions.py`, `flowcell_bridge.py`, `blender_bridge_flowcell\`, a short README, and a relative-path custom-action registry for fresh Blender setup or repair by copying those items into Blender's `scripts\addons` folder. The command backend validates configured overrides, otherwise resolves the newest active valid `%APPDATA%\Blender Foundation\Blender\<version>\scripts\addons\blender_bridge_flowcell` at runtime without writing local config, logs its config/source/final path, clears stale request traffic, and queues normal Blender buttons without waiting on `response.json`. Direct clicks plus `Pop`/`Fan` selections all route that marker to the managed percentages popout, and repeated opens create duplicate Codex Usage popouts instead of generic label-only script popouts.
