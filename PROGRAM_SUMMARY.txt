Maintenance rule
----------------
This file is the living summary for the FlowCell workspace. Any time FlowCell is updated, fixed, reorganized, or extended, update this file in the same change so it stays accurate.

Purpose
-------
FlowCell is a Windows desktop automation shell for creative and system workflows. It now uses a Tauri v2 + React + TypeScript frontend with an AutoHotkey v2 and PowerShell command backend to manage:

- program tabs
- editable panel tabs
- script and macro buttons
- hotkey bindings
- recorded macros
- panel popouts
- tool popouts
- popout layout snapshots
- Blender bridge actions

Open-source repository model
----------------------------
The repository is now arranged for public GitHub use. Tracked source, docs, examples, and tooling remain in the repo. Mutable user state, machine-specific settings, logs, and build artifacts are kept in ignored local storage.
FlowCell also now includes donation support through .github\FUNDING.yml, a README support badge link, and a Stripe Payment Link.
Contributor guidance now explicitly requires relative repo-path resolution instead of tracked machine-specific absolute paths.

UI architecture layers
----------------------
FlowCell UI now uses an explicit three-layer split for interactive button surfaces:

- State Layer: FlowCell state is the only source of truth for button identity, bindings, script targets, panel membership, popout/layout participation, selected tabs, persistence, the app-wide `AppTheme` token set, `StyleGroupId` / `style_group_id` assignments, and persisted compound-tool state such as per-owner alignment modifiers.
- State Layer now also persists button `command_id` values plus embedded tool option records in `ToolOptionStates`, so execution intent and tool settings stay in state instead of frontend-only globals.
- State Layer now resolves and validates button metadata before execution, including relative script-target normalization against the owning program configuration, and writes explicit `State resolved metadata...` plus `State validation...` log entries.
- Functional Host Layer: host-owned behavior for button command emission, compound child-action dispatch, selection checkboxes, drag/reorder surfaces, context menu integration, popout interactions, and persistence participation. Main-window buttons, panel popout buttons, grouped tool popouts, compound tool grids, individual tool popouts, embedded flatten/revolve tool actions, and hotkeys now all feed one shared command envelope path before backend execution.
- Functional Host Layer now rejects invalid state targets in the UI layer instead of handing broken button metadata to the backend, emits explicit `Frontend command emitted...` log entries, carries `request_id` plus owner/child fanout metadata in the shared envelope, and only applies UI-owned follow-up changes from backend results.
- Visual Skin Layer: render-only visual skin mounting inside host surfaces via style-group metadata lookup with sandboxed boundaries and automatic fallback to default FlowCell visuals if a style group is missing or invalid.
- Visual Skin Layer now writes explicit `Visual Skin rendered appearance...` log entries so appearance rendering stays observable without owning any behavior.
- Alignment tools now render as one responsive compound group with three axis rows (`Z`, `Y`, `X`) plus one full-width `Center Everything` row, and each interactive cell is a real host child action that gets its own `style_group_id`-driven visual skin instead of hardcoded widget colors.
- Smart Axis now stores its modes/live state in `ToolOptionStates` under the base owner button and renders as one grouped tool-popout surface (`Base`, `X`, `Y`, `Z`, `Live`) whose owner and fanout child buttons all emit the same typed envelope path through the Tauri gateway and backend command host.
- The dedicated backend command host is now the only active executor for FlowCell button actions. It writes `Backend command received...`, `State/payload validation...`, `Resolved execution target...`, `Bridge/runner execution result...`, and `Final user-visible status...` log entries in `FlowCell\local\logs\command_host.log`, while the Tauri gateway normalizes a stable frontend result shape (`ok`, `request_id`, `status`, `message`, `details`, `logs`, `exit_code`, `duration_ms`).

Program-tab and panel-tab strips now apply host-style item surfaces through shared tab item style generation so their visuals are aligned with the same host/skin model while behavior ownership remains in the host layer.

Local-only runtime storage
--------------------------
FlowCell now keeps mutable runtime data in FlowCell\local, which is ignored by Git.

Local runtime paths:
- FlowCell\local\bindings.ini: hotkeys, program tab metadata, and shortcut bindings.
- FlowCell\local\flowcell_state.json: selected program, selected panel, button layout, panel state, startup popout-only preference, popout state, and tool popout state.
- FlowCell\local\scan_state.ini: Illustrator scan cache/state.
- FlowCell\local\layouts: saved popout layout snapshots.
- FlowCell\local\panel_saves: saved panel exports.
- FlowCell\local\recorded_actions: recorded macro definitions.
- FlowCell\local\logs: UI, backend, launcher, and action status logs.
- FlowCell\local\logs\command_host.log: command-host validation, target resolution, runner/bridge execution, and final status log.
- FlowCell\local\private\local.settings.json: optional machine-specific settings such as private config paths.
- FlowCell\local\temp: generated temp files.
- FlowCell\local\bin: ignored local binaries such as the optional launcher EXE.

This change ensures existing panel configuration, hotkeys, bindings, popout layouts, saved panels, and other user changes remain local and should not be overwritten by GitHub updates.

Illustrator 3D test scripts now resolve their helper macro wrappers from the repo's FlowCell\helpers folder relative to the script location instead of a user-specific codexapp path.

UI-dependent Windows scripts now launch through the backend STA path when their filename indicates dialogs or interactive prompts, including file_update_github.ps1, fix_this_folder_from_explorer.ps1, and the monitor layout dialog helpers.

FlowCell's backend runner now respects child process exit codes and preserves script-written status output for CLI/button launches, so Update GitHub reports real verified Git success or failure instead of a generic launcher result.
The Update GitHub script also disables PowerShell's native-command stderr escalation around Git calls so normal push progress output does not get misreported as a failure after a successful push.
The Update GitHub flow now opens a topmost commit-message dialog that shows the resolved repo path, writes clearer intermediate status text while waiting/committing, and gets a longer FlowCell script timeout so interactive git pushes are not killed after the generic 120-second window.
Slim FlowCell popouts now use a definite viewport-height shell with explicit `minmax(0, 1fr)` content tracks, so compact tool layouts can consume extra vertical space instead of collapsing to intrinsic content height.
Panel `Fan` popouts now compute their expanded bounds from the real owner/child button geometry instead of holding onto a seeded rectangle, then collapse back to the owner pill footprint and persist only that collapsed anchor position so the transparent fan window no longer keeps a large idle slab over Blender.
Panel `Fan` popouts now measure the visible owner/child pills directly, reopen from the saved anchor position with a small collapsed footprint instead of restoring stale saved width/height, and lay child buttons out in a tight centered grid above the owner so the transparent native window wraps the visible buttons more closely and stops clipping the top row during hover-open.
Panel `Fan` popouts now also create their Tauri window with `shadow: false` alongside `decorations: false` / `transparent: true`, restore the fan pill labels after the earlier wrapper CSS regression, and skip popout-bound persistence until the measured fan metrics are ready so raw expanded rectangles are less likely to be written back as collapsed bounds.
Tool popouts now reuse an already-open Tauri window with the same label by repositioning/focusing it instead of closing and recreating it; this avoids the old-window close handler deleting the saved `ToolPopouts` record during reopen, which was causing panel-fan windows to disappear immediately after opening.
Panel `Fan` popouts now render the owner pill at the collapsed window origin while idle and only shift it into the expanded anchored position while open, so shrinking the native window back to the owner footprint no longer clips the owner button offscreen and makes the fan appear to vanish.
Panel `Fan` geometry now measures stable intrinsic owner/child pill sizes from the rendered DOM instead of transformed animation bounds, which prevents the native panel-fan window from repeatedly resizing itself during hover-open and reduces the flash-open/instant-collapse behavior caused by the window chasing animated measurements.
Panel `Fan` measurement no longer subscribes to the popout window's own resize event; the layout now tracks actual pill-size changes through DOM observers only, which avoids panel-fan bounds recalculating in response to the very resize animation they are trying to drive.
Fanout implementation note: the old layered panel-fan/floating-fanout experiments have been replaced by one deterministic model. Hidden measurement pills supply stable intrinsic owner/child sizes, both fanout variants compute absolute child rectangles in window coordinates, native bounds are derived only from collapsed owner bounds plus those measured rectangles, expanded windows no longer feed their own resize events back into layout, child visibility is separated from native expand/collapse so only the pills animate, and transparent hover/pointer retention now comes only from the visible owner/child pills instead of the empty expanded window area.
Panel `Fan` popout move/resize persistence now reads the live open-state and metrics refs instead of stale effect-closure values. That prevents the first open-cycle resize events from being misread as a collapsed panel-fan move, which was forcing collapsed-bound saves, state reloads, and immediate child-grid disappearance right after the buttons appeared.
Panel `Fan` now notifies the parent popout shell about open/close state directly from the hover handlers instead of waiting for a post-render effect. That makes the main popout window mark itself open before the first native resize events fire, so the opening resize no longer gets handled as a collapsed move/save cycle that immediately tears the child grid back down.
Panel `Fan` no longer persists live move/resize events at all while its Tauri popout exists. The panel-fan window had still been writing collapsed-bound move saves during open, which forced state reloads and made the child buttons vanish right after appearing. Removing live panel-fan move/resize persistence stops that self-reload loop.
Panel `Fan` reopen calls from the main window no longer reapply the small stored collapsed placement onto an already-open panel-fan Tauri window. Existing panel-fan windows are now only shown/focused on reopen, while their live size is left under the panel-fan hover-expansion logic. The default collapsed seed size is also tighter, so the initial hover block stays closer to the visible owner pill.
Panel `Fan` now ignores stale saved width/height when reopening its Tauri window and reuses only the saved anchor position, while the React fan root itself stays exactly owner-pill sized while closed and switches to the measured expanded bounds only after hover-open. Release model
-------------
The repository is source-only by default.

- EXE files and build artifacts are ignored.
- Built binaries are not committed to the repo.
- The optional launcher source is tracked under tools\launcher.
- Release binaries should be produced locally and later distributed through GitHub Releases.

Current maintenance expectations
--------------------------------
- Keep public source in tracked repo folders.
- Keep mutable runtime data in FlowCell\local.
- Keep Blender FlowCell button scripts in Blender\FlowCellButtons only.
- Keep Blender support scripts in Blender\SupportScripts.
- Keep Illustrator and Windows user-facing scripts directly in their program folder.
- Keep Photoshop repo-safe public scripts directly in Photoshop.
- Keep Illustrator\HelperScripts for internal non-button helper scripts.
- Prefer filename prefixes for file organization only.
- Update this summary whenever the repository structure or FlowCell behavior changes.
