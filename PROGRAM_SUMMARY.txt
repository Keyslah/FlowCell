FlowCell Program Summary
Last updated: 2026-07-17

Purpose
-------
FlowCell is a Windows desktop command surface for program-specific script Buttons, editable skins and geometry, popouts/fans, program bridges, layouts, bindings, and local automation.

Current Architecture
--------------------
- The canonical Button system is the only Button runtime. It owns main-panel Buttons, tool-set children, popouts, fans, skins, geometry, editing, activation animations, and execution targets.
- `flowcellbackend/local/button-system/button-state.json` is canonical Button state.
- Program manifests and owned source packages replace program-specific script/button inventories in application core.
- Legacy program-script records and source comment directives are migration input only; `FlowCellFrontend/src-tauri/src/program_sources/migrate.rs` is their sole reader and preserves raw legacy Button metadata through an owned migration package.
- Keep this file structural and current. Detailed behavior belongs in the focused docs and implementation.

Repository Map
--------------
- `FlowCellFrontend/src/button/` owns the Button schema, host, renderer, surfaces, editor, skins, state, runtime dispatch, geometry, popouts, fans, activation animations, and Button windows; `FlowCellFrontend/src/assets/button-animations/` owns bundled transparent sprite assets.
- `FlowCellFrontend/src/pages/main/MainButtonHost.tsx` integrates canonical Buttons into the main window.
- `FlowCellFrontend/src-tauri/src/button_state.rs` owns revisioned, atomic Button-state commits and uninstall coordination.
- `FlowCellFrontend/src-tauri/src/program_sources/` owns program manifest loading, versioned bundled-source synchronization, source install/update, active records, execution, deletion, durable transactions, and one-time migration.
- `FlowCellFrontend/src-tauri/src/main.rs` is composition only. Focused owners under `FlowCellFrontend/src-tauri/src/commands/` handle programs, bindings and child-Button hotkeys, macros, files/recycling, execution bridges, windows/topmost, layouts, organization, Illustrator utilities, slicers, and themes.
- `flowcellbackend/` is the canonical AutoHotkey/PowerShell backend and launcher root.
- `flowcellbackend/local/` is ignored durable runtime state: bindings, Button state, layouts, logs, profiles, command payloads, and private configuration.
- `Programs/` contains manifest-defined program packages, tracked Git Scripts catalogs, ignored owned Local Scripts installs, active panel source records, and runner adapters.
- `docs/buttons.md` is the Button owner/file map. `docs/repository-layout.md`, `docs/flowcell-program-registry.md`, `docs/flowcell-toolset-manifest.md`, and `docs/blender-scripts.md` define source/package contracts.

Canonical Contracts
-------------------
- `button-state.json` owns Button records, placements, surfaces, skins, popouts, fans, per-Button activation animation assignments and physical bounds, and settings. No parallel Button state file is authoritative.
- Canonical Button-state reads are recovered, read-only snapshots. Main alone performs legacy migration and registered bundled-source synchronization once during startup, publishing only a changed authoritative revision; secondary windows subscribe before their initial pure load and never synchronize program sources as a render-time side effect. Main accepts documents monotonically by revision and refreshes the active panel's source list when its canonical source inventory changes, after the first accepted document, and after bootstrap completes so an earlier filesystem read cannot strand newly synchronized sources off-screen.
- Button-owned Local Scripts packages are the installed source of truth. Each source owner has `Programs/<Program>/<Program> Local Scripts/<ownerButtonId>/` plus `Programs/<Program>/Panels/<Panel>/<ownerButtonId>.flowcell-source.json`.
- `<Program> Git Scripts` is a tracked catalog only. Add copies from the selected source into the owned Local Scripts package. Ordinary catalog edits do not modify installed Buttons; a program manifest may explicitly version and synchronize named `bundledSources`, preserving existing owner IDs and presentation.
- Add creates a fresh owner. Selecting a manifest package's declared entry file promotes the whole package; selecting a companion file is rejected. Buttons Editor Update replaces source while preserving owner/placement IDs, presentation, dependent popout/fan references, and the owner's `runtime/` state. Tool-set slot removal/rename requires delete/re-add; an explicit append-only update policy may add deterministic missing children without replacing the surviving graph. Delete removes the complete owned Button graph, bindings, program runtime artifacts, active record, Local package, and runtime state. Cancel and native Editor close discard staged imports sequentially; failed cleanup keeps the Editor open and the staged owner tracked for retry.
- Buttons Editor navigation resolves the exact occurrence through Program, Panel, Button, and Placement selectors; placement identity selects the Main page, Pop, or saved Fan surface while the workspace keeps every sibling Button visible and editable. A panel owner without a saved Fan offers `Fan — Default grid`; selecting it creates a draft setup from that panel's single-script Buttons and focuses the exact Fan owner placement. A tool-set owner offers `Main page` (its single owner placement) plus a `Pop — <name>` option that opens the tool-set popout surface in the workspace with every child Button visible; selecting it focuses the first child placement so each child can be selected and edited individually. Fan Builder exposes the current panel's single-script Buttons and Tool Set owners by canonical ID; an exact nonempty subset can create a new Fan or update the active Fan while retaining its setup ID, surviving placement/skin geometry, rules, animation, and surviving Tool Set anchors.
- Any enabled Button that executes an action or toggles a panel/tool-set owner can assign the `Plus Rise` activation preset from the Inspector. Its transparent setup presenter renders only the static PNG at its true maximum animation size; app-managed invisible edge/corner resizing remains locked to the source's 283:295 ratio, and the shared Button record saves that semantic maximum-size rectangle in whole physical desktop pixels. Playback derives a separate larger cursor-ignored transparent travel canvas, then uses 61 linearly timed motion samples over 1.2 seconds to rise continuously from faint/small through opaque/full size before shrinking and fading out. Runtime requests from Main, Pop, Fan, and Editor use deterministic live-window coordinator election and are generation-scoped. Only the primary activation event triggers it; selection and paired release/hover events do not.
- Every real program panel has one source-free `panel-owner` Button on that program's main panel-rail surface. It is the actual main-page panel selector, including Utility, and panel/program folder lifecycle creates, renames, or removes it; generic Button deletion cannot remove it. Panel discovery during ordinary program navigation is read-only: it publishes the filesystem panel list immediately, uses a fallback panel control while canonical presentation loads, and never prunes or rewrites owners from a potentially stale discovery snapshot. Add Program and Add Panel explicitly ensure owners; Add Panel treats an existing case-insensitive folder match as an idempotent refresh/select instead of stranding a healthy program behind a duplicate-name alert.
- A panel owner's Main placement and each saved Fan placement reuse that same Button identity while retaining placement-specific geometry and skin overrides. Fan Run preview uses the saved open, close, and pinned rules; the default starts on the real owner, hover opens and hover-out collapses, owner click pins, and the next pinned click collapses. Edit mode exposes the complete grid, and the Editor never creates an empty fan merely to offer a Fan choice.
- A fan setup's `collapsedPanelOwnerBounds` desktop anchor is optional: it is absent until the user space-drags the collapsed fan, which persists the visible semantic frame in real physical desktop pixels. The owner frame is derived from its applied visual envelope and effective WebView pixel ratio while preserving the owner's surface origin, so shadows and other overflow do not clip or shift the later expanded frame. Unanchored fans open centered over the launching window, and loading strips legacy `{left: 0, top: 0}` placeholder anchors.
- The main-page Fan button prioritizes an exact nonempty panel selection (single-script Buttons plus Tool Set owners), labels itself `Fan (N)`, creates/reuses that member-set Fan, and opens it. With no selection it retains the saved/default workflow: no saved setup creates a persisted generic Fan, one opens directly, and several show the saved-setup menu. `ensureFanSetup` is idempotent per member set.
- Panel/program rename preserves stable Button and presentation IDs while migrating canonical identities, active/install records, typed targets, source paths, catalog manifests, panels, fans, and popouts. Program rename uses one durable outer journal with exact previous/next bindings and canonical Button documents; atomic writes, case-only temporary moves, startup recovery, external-drift refusal, live backend reload, and token recovery keep the native and canonical sides on the same proved state.
- Program removal first unregisters under an opaque native rollback snapshot, then commits canonical/source cleanup and finalizes; a failed canonical commit restores registration only while bindings still match the post-unregister state, otherwise it preserves the rollback token and unrelated changes. The available program package is kept, and obsolete-window closing is best-effort after commit. Panel deletion holds the source quarantine guard and refuses to recycle a panel that gained an active source during the canonical/native handoff.
- User-facing deletions go to the Recycle Bin. Source transactions use recoverable JSON writes and durable quarantine journals; startup finishes committed cleanup or rolls back pre-commit work after interruption.
- `flowcell.program.json` defines program identity, folder roles, allowed source types, runner, native owner policy, shortcut profile, and optional versioned bundled source contributions. Only registered programs are synchronized; Add Program may install declared starters, and required contributions self-repair when missing.
- `flowcell.script.json` describes a single-script catalog package. `flowcell.toolset.json` describes one owner, child slots/payloads, optional tool-set layout/fields, and optional manifest-selected page presentation.
- Tool pages do not create another Button type. Illustrator Layer Tree is an installed single-script owner that opens the reusable capability-backed `tree-inspector`; Blender Theme remains a canonical tool-set owner whose manifest selects the reusable `theme-workbench` presentation. Their native windows close when the owning contribution is removed, renamed, or reconfigured, and both disappear with their program registration/package state.
- Tool-set source refresh resolves child slots from saved metadata, typed actions, or the legacy deterministic child ID, then writes current slot metadata. This lets older Theme owners adopt manifest-driven core actions and page presentation without replacing their Button graph or losing customized owner IDs.
- Numbered `bindings.ini` records have two target contracts. Existing single-script bindings remain path-based `ScriptPath` records registered and executed by the resident AutoHotkey backend even when the Tauri/frontend surface is closed. Tool-set child bindings store `TargetKind=tool-set-child` plus canonical `ButtonId` and `OwnerButtonId`; only the running Tauri process registers their supported keyboard accelerators, refreshes them immediately after Binds changes, targets the active expanded owner popout, and feeds the mounted child through its normal ButtonHost press lifecycle. A failed native registration rolls the binding change back. No child payload or field snapshot is stored in the binding.
- The Theme workbench persists declared fields, darkness level, and named darkness profiles per installed owner. Its manifest drives palette browse/tone/application chaining, deterministic Refill, per-bucket Apply, and package Save/Open/Previous/Next workflows; package loads reapply the theme and optional picture. Generic format-aware storage preserves only declared fields/assets, accepts mapped legacy Theme files/packages, stages new packages before publication, and migrates the old page's local fields/profiles without deleting their legacy copies. Relative Theme assets resolve from the installed source package, and read/absorb bridge commands bypass Blender undo entries. The reusable renderer contains no Blender-specific slot or field names.
- Normal execution resolves only a valid `.flowcell-source.json` record whose installed source is inside its matching owner Local Scripts package.

Button Host And Skin Contract
-----------------------------
- The functional host owns interaction state, keyboard/pointer behavior, accessibility, validation, dispatch, and lifecycle.
- An unmodified Main-page Button click executes its primary action immediately. Ctrl/Shift/Meta-click toggles multi-selection with a visible outline; execution does not depend on a double-click timer, and a short duplicate-release guard prevents one physical double-click from dispatching the action twice.
- Skins are render-only and isolated. They cannot execute actions, mutate state, own bindings, or define source targets.
- Every skin contains exactly one measurable `[data-core]` and zero or one `{{label}}` token inside it. Textless and animation-only skins receive no synthesized text or fallback face; the saved Button label still supplies the accessible name.
- The compiler lifts the core's inline `style` into a lowest-priority `[data-core]` rule so ordinary state declarations override that core; nested visuals remain literal and consume custom properties initialized in Base. Skin paste headers tolerate whitespace and case.
- Placement `matchHitboxToSkin` defaults on, scales the complete authored skin root from its measured `[data-core]`, normalizes authored core offsets to the placement origin, and reconciles Editor geometry to the transformed core; turning it off retains core-only sizing. `allowStretching` defaults off, so editor drag and numeric width/height edits keep the current aspect ratio; enabling it permits independent axes, while Shift still temporarily locks them.
- After optional label injection and host scaling, the transformed `[data-core]` is the Button hitbox for DOM, Editor selection/collision geometry, and transparent native-window hit testing. Normal Edit drag and resize sample the complete pointer path and stop at the furthest valid edge without reflowing the workspace with collision warnings. The separate undoable Reorder mode pulls the grabbed Button out of reflow so it follows the pointer at animation-frame speed, preserves the current visual wrap width and row top offsets so every row maps to its visible drop target while variable-width Buttons can rebalance, chooses a stable insertion slot with hysteresis, closes horizontal gaps within each row, smoothly moves neighboring Buttons out of the way, and normalizes saved placement z-index; `Snap to top left corner` gaplessly compacts that saved order from surface origin without changing Button sizes. No compatibility rectangle is overlaid and authored skin source is never rewritten for sizing.
- Placements may save a live `textSizeOverride`; null uses the skin's authored size, while `minimumFontSize` is only the lower bound used when text fitting shrinks a label. Inspector Label and Font size edits publish to attached native Pop/Fan draft windows. Editing skin source while focused on a program panel immediately assigns that skin to every Button placement on that panel surface without reassigning placements elsewhere; any placement already referencing the same shared skin ID also renders the source edit. The Skin editor's Text Preview Bench is explicitly preview-only.
- Visual overflow and active visual state are measured separately from the interactive core. Active hover/press/hold/play measurement may expand the semantic content envelope inside the fixed transparent canvas without changing the authored skin, native host bounds, or `[data-core]` hit testing.
- A mounted skin's shadow DOM is stable: it remounts only when the compiled skin identity (skin id + source fingerprint), a rendered label, or text-fit inputs change. Functional label edits do not remount a textless skin. Parent re-renders, re-cloned documents, and recreated callbacks never rebuild it (a rebuild restarts every skin animation), and placement resizes re-run text fit in place. Host pointer/keyboard listeners likewise stay attached across re-renders, and transparent Pop/Fan windows synthesize the `pointerleave` a cursor-ignoring window would otherwise never deliver.
- Skin source, validation, compilation, and rendering live only under `FlowCellFrontend/src/button/skins/`; there is no separate skin registry.

Program And Bridge Runtime
--------------------------
- Startup preflight reads `Programs/*/flowcell.program.json` but validates immutable catalog/support directories, declared runner adapter files, mutable roots, and refreshed bindings only for programs already registered in `flowcellbackend/local/bindings.ini`; an available package alone has no runtime presence.
- The resident AutoHotkey backend launches the Windows Temp Shots overlay directly, then starts the installed package's sibling PowerShell saver asynchronously; cancelling one snip does not block the next launch.
- Each registered program selects its transport through `flowcell.program.json`; runner code may know that transport but never owns a pre-baked script or Button inventory.
- The Windows script runner keeps canonical ownership validation intact, then converts Rust's extended-length (`\\?\`) source spelling to the equivalent ordinary DOS/UNC path before launching child processes so Windows PowerShell 5.1 can resolve `$PSScriptRoot` and adjacent package files.
- Catalog manifests may name only the small registered core-action allowlist for utility services; those services become reachable only through an installed owner package and its validated capability/active identity.
- Program compatibility action handlers are loaded only when canonical installed owners still reference them. Their commit-driven registration is serialized against the latest canonical need, subscribes before its initial state load, and cannot activate after window disposal. Generic file, palette, field/package-state, legacy-state migration, and tool-page services remain program-neutral and capability-gated where they touch installed-owner or local program data.
- Save Clipboard Text is a shareable, repeat-installable Windows single-script package: each Button accepts only clipboard text, writes a collision-safe timestamped UTF-8 file, keeps an independent destination in its owner-preserved `runtime/` state, and can reselect that folder while Shift is held (with a user-local fallback for standalone use).
- Codex Micro is a catalog-only set of closed Windows script packages. Its independently installable entries use the installed Codex desktop package's exact AppsFolder identity and coordinate-free UI Automation controls for verified task, dictation, navigation, stop, reasoning, and read-only status actions; dynamic numbered slots and unverified approval commands are documented but intentionally have no runnable entries.
- Blender installs require a top-level `run_flowcell_action(context=None, data=None)`. Deployment generates an owner-scoped bridge action from the installed Local source.
- Blender Rename Selected opens its multi-object prompt asynchronously through Windows PowerShell/WPF, then applies the confirmed names on Blender's timer; it does not depend on Blender's optional Tkinter runtime.
- Named Blender button events execute their declared bridge actions. A declared `pressDown` owns activation instead of also firing the normal release click; paired `pressDown`/`pressUp` events run in order and synthesize their declared hover session for keyboard use. Cycle Collection captures its private visibility baseline on hover, shows one object while held, restores object plus collection-layer visibility on release, and clears the private snapshot on leave without touching the manual baseline.
- The installed Blender Alignment Tool Set normalizes every child slot into an explicit axis/mode command. The active object remains the reference target, other selected objects move, and Origin slots use each moved object's origin as the source while still targeting the active object's bounds center.
- Blender actions that remove or replace Blender data capture response metadata before invalidating the corresponding RNA references; Split strips Blender's generated `.###` suffix and names results `<source> 1` through `<source> N`.
- Blender bridge/add-on deployment changes require reloading the FlowCell add-on or restarting Blender before runtime verification.
- Base Blender add-on repair preserves the installed owner-action registry and `ManagedActions` directory instead of replacing them with empty bundle templates. Blender owner install/sync reads UTF-8 source and registry files explicitly, passes each runtime wrapper its installed source-package root, and validates registration without executing program actions. Bulk recovery can register sources with `Install-BlenderFlowCellButtons.ps1 -SkipSync`, then normalize the completed registry once.
- Tool-set child payloads merge manifest defaults, child defaults, and live Button field/behavior values; child slots are validated against the active record. A child hotkey therefore carries the same current field state, state-only patches, file activation, payload template, core action, and custom tool-page completion behavior as activating that mounted child onscreen.
- The Illustrator Layers Builder panel remains 20 independent single-script owners. Its versioned catalog contributions update those installed sources in place so the highlight prelude is restored without changing IDs or converting the panel to a tool set; Layer Tree is a separate required owner and invalidates through the generic program-data event. The Illustrator capability adapter normalizes ordinary and Windows extended-length (`\\?\`) paths before enforcing the Button-owned Local Scripts boundary, so Rust-canonicalized installed sources pass the same fail-closed containment check and the tree can scan the active document.
- The AutoHotkey backend creates Illustrator scanner/UIA services only while Illustrator is registered, and Blender theme restore timers are enabled only while an installed owner declares that capability.

Managed Windows And Layouts
---------------------------
- `FlowCellFrontend/src/button/windows/`, `FlowCellFrontend/src/button/animations/`, `FlowCellFrontend/src/lib/windowContext.ts`, `FlowCellFrontend/src/lib/layoutSnapshots.ts`, and `FlowCellFrontend/src/AppBase.tsx` own Button editor, popout, fan, and transient activation-presenter window creation/routing/restore.
- Illustrator-scoped popouts temporarily detach their native owner while Windows taskbar previews are active, retain the real Illustrator owner through that preview, and restore it afterward so activating another program immediately returns the popout behind Illustrator.
- Program-scoped Pop/Fan and tool-page windows use one native placement state machine. Only an exact manifest `processNames` match for the actual foreground process may select `TOPMOST`; a focused FlowCell Button window is only a normal-band continuation of the last proven owning program and never counts as a topmost match. Taskbar previews and unrelated programs place every scoped window explicitly behind the real foreground HWND (or at the bottom as a fail-safe), so bare `HWND_NOTOPMOST` cannot strand Blender controls over Illustrator or vice versa.
- Layout restore and collapse/expand use saved physical-pixel managed-window bounds and canonical Button surface identities, preserving mixed-DPI size and owner anchors. Restore resolves its target program and panel before exposing either selection, then performs a request-scoped source refresh; whichever matching refresh wins also consumes the target-scoped saved Button selection, including an explicitly empty selection, instead of relying on unchanged React dependencies to reload cleared Buttons.
- Pop and Fan setups save a `surface`, `hitbox`, or `visual` window-fit mode. Their non-resizable transparent Tauri host is a large fixed canvas covering the active monitor work area (and any semantic frame outside it), starts cursor-ignored, and becomes cursor-active only when its native owning-program entitlement is active and the pointer is over a Button host, tool field, or Pop resize handle; every transparent gap and every wrong-program state therefore passes clicks to the application underneath. Hitbox/visual fits, hover/press/hold/play overflow, Fan expansion, and tool-set collapse/expansion move and resize only an absolutely positioned semantic content frame inside that canvas, preserving one invariant physical surface origin instead of repeatedly moving the HWND. The canvas grows or rehomes only when content would escape it, including monitor-edge drag/resize and mixed-DPI transitions. An unsized Pop starts at one design pixel per WebView CSS pixel; restored physical bounds use the destination WebView's effective pixel ratio, and scaled skin measurement retains skin-root and animated shadow/outline scale while normalizing ancestor content scale into design units. Hold Space and drag any visible Button to move the semantic frame; Pop corner handles preserve aspect and the opposite corner. On release, real physical-pixel Pop/Fan bounds and semantic layout snapshots persist, while transient active envelopes and the large native canvas bounds never do.
- One shared native input worker samples cursor and modifier state and emits only changed snapshots; each Pop/Fan reacts to those changes plus local geometry/DOM invalidation instead of polling native input every frame. Scope and input listeners subscribe before querying their initial state, retry transient setup/read failures, and fail closed to cursor-ignored; the serialized native cursor-style controller also retries a failed `setIgnoreCursorEvents` call and converges to the newest requested state. Physical semantic bounds and cursor snapshots are mapped through the WebView's effective pixel ratio (including WebView zoom, with native DPI as fallback), so fixed-canvas placement and synthetic hover stay aligned. The window rejects pointers outside its semantic frame before consulting cached interactive membership, but reads exact viewport rectangles live after position-only frame movement, and it bypasses the render barrier for unchanged envelopes. Active visual overflow is measured only while the authored subtree has running motion plus final settle frames, so finite hover/play transitions stop consuming animation-frame work without changing skin source or hitbox ownership.
- Layout snapshots are strict version 8 `FlowCellWindowLayout` documents and accept only Button editor, popout, and fan windows.
- The transient activation setup/runtime presenters are intentionally outside global layout snapshots: they exist only while configuring or playing, and the last physical bounds persist with the canonical Button assignment.
- The frameless Buttons Editor window renders its own title bar (all load/error/ready states): drag the bar to move, double-click it to maximize/restore, with minimize, maximize/restore, and close controls. Close routes through the window's close-requested handler so staged-import cleanup still runs. Layout capture/restore and ordinary reopen reject Windows' `-32000` minimized sentinel bounds, discard stale registered snapshots, and recover the Editor at its default placement.
- Other FlowCell utility windows remain managed Tauri windows but do not own a separate Button implementation.
- `FlowCellFrontend/src-tauri/capabilities/default.json` must list every managed or transient window label and every window/webview command the frontend calls, including the activation presenter, both background-color grants for transparent windows, and the force-destroy grant used only after Editor cleanup; a missing grant surfaces as a runtime "not allowed" ACL error, and changes to it require a Tauri rebuild.

Validation
----------
- Frontend/Tauri changes: run the relevant frontend build; use `flowcellbackend/helpers/Start-FlowCellFrontend.ps1` with `-ForceRestart` when the running frontend must refresh.
- Rust changes: run `cargo check` plus focused tests.
- AutoHotkey changes: validate with AutoHotkey v2 and restart the hidden backend.
- PowerShell changes: parse-check touched scripts and run the narrow behavior test when practical.
- Blender source/bridge changes: compile-check Python where applicable and verify after add-on reload or Blender restart.
- Documentation-only changes: validate headings, links/paths, and stale-term removal; no application build is required.
- Portable program ZIPs contain only Git-tracked package files, require a tracked program manifest, and reject manifest-declared mutable folders, reparse points, containment escapes, and unsafe archive members; the Core ZIP contains no `Programs/` payload.
